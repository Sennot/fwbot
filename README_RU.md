# Frame Window Lab

Исходный код мода для **Geometry Dash 2.2081, Geode 5.8.2, Windows x64**.

Мод импортирует успешный макрос `.gdr` / `.gdr2`, сдвигает выбранные нажатия и отпускания и заново проигрывает варианты через физику самой Geometry Dash. Он измеряет допустимые моменты ввода при фиксированных остальных действиях.

**Статус:** реализован исходник с интерфейсом, движком, импортом, экспортом и Windows workflow. Переносимое ядро проверено локально. Сборка `.geode` на Windows и испытания в запущенной игре в этой среде не проводились. До игровых испытаний это кандидат на тестирование, а не подтверждённая стабильная версия. Подробности — `VALIDATION.md`.

## Получить .geode через GitHub

1. Создай репозиторий GitHub и загрузи **содержимое** папки `frame-window-lab` в его корень. `mod.json`, `CMakeLists.txt` и папка `.github` должны лежать непосредственно в корне репозитория. Не теряй скрытую папку `.github` при копировании.
2. Открой **Actions → Build Frame Window Lab (Windows x64)**. Workflow запускается при push, pull request и вручную через **Run workflow**.
3. Дождись успешного завершения. Workflow сначала проверяет импорт и алгоритмы, затем собирает мод официальным Geode build action. SDK и bindings закреплены в проекте.
4. Внизу страницы запуска скачай artifact **FrameWindowLab-Windows-x64**. Распакуй из него `.geode` и помести в `Geometry Dash/geode/mods`, затем перезапусти игру.

Если сборка красная, `.geode` не готов: открой первый упавший шаг и сохрани полный лог. Переименование ZIP с исходником в `.geode` не устанавливает мод. Другие платформы этот workflow не собирает.

## Что реализовано

| Возможность | Поведение |
|---|---|
| Cube, ship, wave, ball, UFO, robot, spider, swing | Общий движок нативного воспроизведения; без приближённых формул траектории |
| Mini, обратная гравитация, переходы режимов | Состояние обрабатывает сама игра |
| Dual / два игрока | Отдельные каналы P1 и P2; можно сканировать одного или обоих |
| Platformer | Чтение кнопок 1–3 и воспроизведение непрерывного макроса без запланированных смертей |
| Single edge | Сдвигается одно нажатие или отпускание, остальные события фиксированы |
| Hold pair | Нажатие и следующее отпускание той же кнопки сдвигаются вместе; длительность удержания сохраняется |
| Отпускания ship/wave | Проверяются такими же полноценными событиями, как нажатия |
| Несколько успешных интервалов | Сохраняются отдельно, с точными проверенными смещениями |
| Повторные проверки | Несколько базовых прогонов, повторы каждого смещения, контроль исходного макроса между строками |
| Removal test | Проверяется результат удаления выбранного события или пары |
| Предпросмотр | Воспроизведение выбранного смещения с обычной скоростью |
| Результаты | Автосохранение завершённых строк, частичный отчёт при остановке, JSON и CSV |

Перечень режимов описывает охват реализации. Подтверждённой игровой матрицы совместимости пока нет.

## Первое измерение

1. Подготовь макрос при **240 TPS**, без CBF, коррекций позиции, speedhack и ботов, которые вмешиваются в воспроизведение. Не меняй только число FPS в метаданных старого макроса: это не преобразует физику или тайминги.
2. Открой соответствующий уровень в normal mode, без StartPos. LDM должен соответствовать метаданным макроса. Для безопасного тестирования изменений уровня удобно использовать его неизменённую копию.
3. Нажми паузу, затем **FW Lab → Import**. Выбери `.gdr` или `.gdr2` в диалоге Windows.
4. Для первого запуска выбери небольшой диапазон, например **First input = 1**, **Last input = 5**, **Radius = 3**. Номера событий в интерфейсе начинаются с **1**, ticks — с **0**.
5. **End tick = 0** означает проверку до фактического завершения уровня. Положительное значение проверяет выживание до начала указанного tick; это более слабое условие, чем прохождение уровня.
6. Оставь **Frame offset = 0**. Если исходный макрос не воспроизводится из-за соглашения бота о нумерации кадров, проверь известный сдвиг, например −1 или +1. Мод не подбирает его автоматически и не маскирует неуспешную базу.
7. Выбери press/release, P1/P2 и Single edge / Hold pair. В Hold pair выбираются нажатия; парное отпускание может находиться за пределами выбранного диапазона номеров.
8. Нажми **Start scan**. Игра снимается с паузы. **Esc** ставит анализ на паузу; через **FW Lab → Resume** продолжается тот же анализ. Текущий незавершённый прогон при возобновлении начинается заново, уже завершённые пробы сохраняются.
9. Открой **Results**, выбери строку. **Early/Late** подставляют границы интервала вокруг исходного ввода, **Play** проигрывает выбранный вариант. **Export** сохраняет отчёты и открывает папку.

Если ID копии отличается, включи **Options → Allow copy ID**. Это разрешает только расхождение ID: геометрия, настройки уровня, LDM и физика всё равно должны совпадать. Предпросмотр отчёта дополнительно проверяет отпечаток строки уровня.

Настройка **Steps per render** задаёт максимум шагов планировщика между отрисовками. Дополнительно действует бюджет около 10 мс на пакет. Это ускорение симуляции, а не изменение TPS. Чем длиннее уровень и больше событий, радиус и повторы, тем дольше анализ: каждый вариант проигрывается с начала.

## Как читать результаты

Допустим, нажатию на tick 100 соответствуют успешные смещения `-2..1; 4..5`.

- Окно вокруг исходного ввода: **4 ticks**, то есть ticks 98, 99, 100 и 101.
- Всего успешных смещений: **6**. Это не одно окно размером 6.
- Второй интервал 104–105 показывается отдельно.
- Если крайний успешный tick упирается в радиус, отображается **open bound**: окно может быть шире. Увеличь радиус и повтори анализ.
- Граница из-за соседнего события, начала уровня или выбранного конца обозначается отдельно. Она не означает, что за ней обязательно наступает смерть.
- **partial**: строка ещё не проверена целиком.
- **unstable**: повторы дали разные результаты/моменты окончания либо уровень закончился до выполнения сдвинутого события. Такой tick не включается в успешное окно.
- **timeout**: прохождение не завершилось в заданный предел. Это не доказанный fail.
- **DESYNC**: контрольное состояние перестало совпадать; анализ останавливается, частичные результаты сохраняются.

**Removal = pass** означает только, что конкретный проверенный макрос пережил удаление до выбранной цели. Это не доказательство, что данное нажатие не нужно при других соседних таймингах.

В Single edge изменяется длительность удержания: это полезно для проверки границ ship/wave/robot. В Hold pair измеряется перенос удержания неизменной длины. Совместная двумерная карта всех сочетаний press/release в этой версии не строится.

## Точность и ограничения

- Результат условный: он зависит от остальных фиксированных вводов, seed, версии игры, настроек уровня и цели проверки. Мод не ищет глобальный оптимальный путь и не заменяет субъективную оценку сложности.
- Проверяется сетка **240 TPS с вводом на целых шагах**. CBF, субкадровые нажатия и другие TPS не поддерживаются. Видеокадры монитора не равны измеряемым ticks.
- Планировщик получает фиксированные шаги 1/240 секунды; внутри игры остаются нативные обработки dt, timewarp, триггеров и коллизий. События считаются в `processCommands` без half-tick. Правильность этой привязки для разных экспортёров, особенно с timewarp, требует проверки на реальных макросах.
- При проверке baseline сравниваются отпечатки выбранных полей активных игроков, часов и RNG. Совпадение нескольких прогонов снижает риск рассинхронизации, но не доказывает совпадение всего скрытого состояния игры.
- StartPos, practice checkpoints и макросы с запланированными смертями отклоняются. Полные снимки состояния и восстановление с произвольного кадра не используются.
- Бинарные `.gdr2` читаются по реализации upstream writer версии 2; `.gdr` — MessagePack или JSON. Произвольный файл другого бота, переименованный в `.gdr`, не становится совместимым.
- Расширения и frame fixes читаются/пропускаются, но **не применяются**. Если без них макрос не проходит baseline, окна не измеряются.
- Повторные press/press, release/release и press+release в одном tick одного канала отклоняются как неоднозначные. Одновременные события разных игроков сохраняются.
- Известные вмешивающиеся моды (CBF, xdBot, SiliFork, Silicate, Mega Hack, Eclipse по ID) блокируются при загрузке. Отключи их в Geode и перезапусти игру; выключения отдельной функции внутри такого мода недостаточно. Проверка не обнаруживает все возможные конфликты.
- Импорт ограничен 32 MiB, 100 000 событиями и tick 10 000 000. Радиус — до 10 000. Исчерпывающий большой скан может занимать много времени.
- Во время анализа включается test mode и блокируются сохранение процента, завершение уровня и инкременты статистики; исходные счётчики уровня восстанавливаются. Не используй результаты анализа как легитимное прохождение.
- По завершении/отмене уровень сбрасывается и ставится на паузу. Возобновление после полного закрытия игры по сохранённому JSON пока не реализовано.
- JSON имеет собственную схему `frame-window-lab/1`. Это **не заявленный формат импорта NaNDL**. Для калькулятора можно вручную перенести проверенные окна. Экспортное время `tick / 240` — номинальное, не гарантированная позиция песни при timewarp. Расчёт precision NaNDL в мод не включён.

## Сборка локально

На Windows нужны Git, CMake ≥ 3.25, Ninja, LLVM/Clang ≥ 19, Visual Studio C++ Build Tools с Windows SDK, Geode CLI и SDK 5.8.2. Запускай команды в x64 Developer PowerShell. Укажи `GEODE_SDK` и `GEODE_BINDINGS_REPO_PATH` на установленные копии; для воспроизводимости используй commits из `SOURCES.md`.

```powershell
cmake -S . -B build -G Ninja -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

Только переносимое ядро, без SDK и игры:

```sh
cmake -S . -B core-build -DFWL_BUILD_MOD=OFF -DCMAKE_BUILD_TYPE=Debug
cmake --build core-build --parallel
ctest --test-dir core-build --output-on-failure
```

Файлы `tests/fixtures/*.gdr2` — маленькие синтетические данные, созданные официальным writer для проверки формата; они не являются макросами прохождения игрового уровня.
